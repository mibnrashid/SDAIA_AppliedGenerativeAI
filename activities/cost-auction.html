The cost model, to reuse

Every scenario above is this, with different numbers. Copy it into your own project.

requests_per_month = users × queries_per_user × working_days

cost_per_request   = (input_tokens  / 1e6) × price_per_1M_input
                   + (output_tokens / 1e6) × price_per_1M_output

monthly_cost       = requests_per_month × cost_per_request × (1 − cache_hit_rate)

Where the input tokens actually come from, in a RAG system:
    system prompt        ~200 tokens   (re-sent on every call, forever)
    retrieved chunks     top_k × chunk_size   ← usually 80% of the bill
    conversation history grows with every turn
    the user's question  ~30 tokens

Three levers, in order of effect:
    1. top_k and chunk size   — directly sets the biggest input component
    2. cache hit rate         — a hit costs nothing at all
    3. model choice           — route easy requests to the cheaper model

And remember: Arabic is roughly 2–3× the tokens of the same meaning
in English, so the same product costs more to run in Arabic.
